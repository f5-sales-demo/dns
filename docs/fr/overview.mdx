Ce cas d'usage gère le **DNS faisant autorité sur F5 Distributed Cloud** avec Terraform. Un plan
petit et réutilisable crée une zone DNS primaire et ses enregistrements pour un domaine délégué,
conserve son état dans **Azure Blob Storage**, et exécute plan-on-pull-request / apply-on-merge via
**GitHub Actions**.

## Ce qu'il gère

- Un `xcsh_dns_zone` — une zone **primaire** faisant autorité dans le namespace `system` de F5 XC,
  avec des enregistrements A. Le nom de zone est le domaine délégué (une variable), de sorte que
  le reciblagle est un changement de configuration, et non un changement de code.
- L'état Terraform distant dans Azure, afin que les exécutions soient partageables entre la machine
  d'un opérateur et l'environnement CI.

## Architecture

| Couche | Choix | Pourquoi |
| --- | --- | --- |
| Fournisseur | `f5-sales-demo/xcsh` (registre Terraform) | Généré à partir de l'OpenAPI F5 XC ; gère `xcsh_dns_zone` et les ressources d'équilibrage de charge DNS. S'authentifie avec un jeton API (`Authorization: APIToken <token>`). |
| Backend d'état | `azurerm` (Azure Blob Storage), authentification par clé d'accès | État durable et partagé. L'authentification par clé d'accès est utilisée car l'abonnement n'accorde que le rôle Contributeur, qui ne peut pas attribuer le rôle *Storage Blob Data Contributor* nécessaire à l'authentification sans clé (OIDC / Azure AD). |
| Automatisation | GitHub Actions | Plan à chaque pull request, application lors de la fusion dans `main`. Les coordonnées du backend et les entrées proviennent des **variables** du dépôt ; les informations d'identification proviennent des **secrets**. |

<Aside type="note">
Tous les objets DNS F5 XC doivent résider dans le namespace `system` — l'API rejette les autres
namespaces. Le plan applique cette contrainte avec une règle de validation de variable.
</Aside>

## Par où commencer

Le parcours [Démonstration](/dns/demo/) décrit l'intégralité du cycle de vie de bout en bout :
**Construction** de la zone avec Terraform, **Validation** de sa résolution, **Basculement** avec
un équilibrage de charge DNS, et **Démantèlement**. Commencez par
[Phase 1 — Construction](/dns/demo/phase-1-build/), qui constitue un guide complet pour déployer la
zone, incluant chaque fichier Terraform, le workflow CI, ainsi que les variables et secrets requis.
