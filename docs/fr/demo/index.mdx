Ce guide présente un **exercice DNS complet** sur F5 Distributed Cloud, piloté par Terraform.
Il est structuré en quatre phases qu'un opérateur humain ou un assistant IA peut exécuter de bout en bout. Chaque
phase est idempotente : la réexécuter converge vers le même état.

## Phases de l'exercice

| Phase | Objectif |
| --- | --- |
| [Phase 1 — Construction](/dns/fr/demo/phase-1-build/) | Déployer la zone DNS primaire avec Terraform ; configurer l'état distant et l'intégration continue |
| [Phase 2 — Validation](/dns/fr/demo/phase-2-validate/) | Confirmer que la zone se résout sur l'internet public et que le plan est idempotent |
| [Phase 3 — Basculement](/dns/fr/demo/phase-3-failover/) | Ajouter un équilibreur de charge DNS avec basculement contrôlé par bilan de santé *(en attente du module DNS-LB)* |
| [Phase 4 — Démantèlement](/dns/fr/demo/phase-4-teardown/) | Détruire les objets gérés après confirmation explicite |

## Prérequis

- **Terraform** ≥ 1.5.
- Le fournisseur **`f5-sales-demo/xcsh`** ≥ 3.62.0 (les espaces de noms système uniquement sont définis automatiquement par défaut),
  résolu depuis le registre Terraform — ou une version locale via `dev_overrides`.
- Un **jeton d'API F5 XC** avec accès à l'espace de noms `system`.
- L'**interface en ligne de commande Azure**, connectée avec le rôle Contributeur sur l'abonnement, pour l'initialisation unique du backend d'état.

<Aside type="caution">
Le domaine utilisé ici est délégué à F5 XC, de sorte que les enregistrements que vous créez se résolvent sur l'internet public.
Utilisez un domaine que vous possédez et que vous avez l'intention de gérer — le plan est piloté par des variables précisément pour vous permettre de cibler le vôtre.
</Aside>

Commencez par [Phase 1 — Construction](/dns/fr/demo/phase-1-build/).
