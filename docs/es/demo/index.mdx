Esta guía recorre un **ejercicio DNS completo** en F5 Distributed Cloud, impulsado por Terraform.
Está estructurado en cuatro fases que un operador humano o un asistente de IA puede ejecutar de
principio a fin. Cada fase es idempotente: volver a ejecutarla converge al mismo estado.

## Fases del ejercicio

| Fase | Objetivo |
| --- | --- |
| [Fase 1 — Construcción](/dns/es/demo/phase-1-build/) | Desplegar la zona DNS primaria con Terraform; configurar el estado remoto y CI |
| [Fase 2 — Validación](/dns/es/demo/phase-2-validate/) | Confirmar que la zona se resuelve en internet público y que el plan es idempotente |
| [Fase 3 — Failover](/dns/es/demo/phase-3-failover/) | Agregar un balanceador de carga DNS con failover verificado por estado de salud *(pendiente del módulo DNS-LB)* |
| [Fase 4 — Eliminación](/dns/es/demo/phase-4-teardown/) | Destruir los objetos gestionados tras confirmación explícita |

## Requisitos previos

- **Terraform** ≥ 1.5.
- El proveedor **`f5-sales-demo/xcsh`** ≥ 3.62.0 (los espacios de nombres exclusivos del sistema
  se configuran automáticamente por defecto), resuelto desde el registro de Terraform — o una
  compilación local mediante `dev_overrides`.
- Un **token de API de F5 XC** con acceso al espacio de nombres `system`.
- La **CLI de Azure**, con sesión iniciada como Contributor en la suscripción, para el arranque
  inicial del backend de estado.

<Aside type="caution">
El dominio utilizado aquí está delegado a F5 XC, por lo que los registros que cree se resolverán en internet público.
Utilice un dominio de su propiedad que tenga intención de gestionar — el plan está basado en variables precisamente para que pueda apuntar al suyo propio.
</Aside>

Comience con [Fase 1 — Construcción](/dns/es/demo/phase-1-build/).
