Questa guida illustra un **esercizio DNS completo** su F5 Distributed Cloud, gestito da Terraform.
È strutturata in quattro fasi che un operatore umano o un assistente IA può eseguire dall'inizio alla fine. Ogni
fase è idempotente: rieseguirla converge allo stesso stato.

## Fasi dell'esercizio

| Fase | Obiettivo |
| --- | --- |
| [Fase 1 — Build](/dns/demo/phase-1-build/) | Distribuire la zona DNS primaria con Terraform; configurare lo stato remoto e la CI |
| [Fase 2 — Validate](/dns/demo/phase-2-validate/) | Verificare che la zona si risolva sulla rete internet pubblica e che il piano sia idempotente |
| [Fase 3 — Failover](/dns/demo/phase-3-failover/) | Aggiungere un bilanciatore del carico DNS con failover controllato dallo stato di salute *(in attesa del modulo DNS-LB)* |
| [Fase 4 — Teardown](/dns/demo/phase-4-teardown/) | Eliminare gli oggetti gestiti dopo conferma esplicita |

## Prerequisiti

- **Terraform** ≥ 1.5.
- Il provider **`f5-sales-demo/xcsh`** ≥ 3.62.0 (i namespace di sola gestione di sistema vengono configurati automaticamente per impostazione predefinita),
  risolto dal registro Terraform — o una build locale tramite `dev_overrides`.
- Un **token API F5 XC** con accesso al namespace `system`.
- L'**Azure CLI**, autenticato con il ruolo Contributor sulla sottoscrizione, per il bootstrap una-tantum del
  backend di stato.

<Aside type="caution">
Il dominio utilizzato qui è delegato a F5 XC, pertanto i record creati vengono risolti sulla rete internet pubblica.
Utilizzare un dominio di propria titolarità che si intende gestire — il piano è basato su variabili proprio per consentire di puntare al
proprio dominio.
</Aside>

Iniziare con la [Fase 1 — Build](/dns/demo/phase-1-build/).
