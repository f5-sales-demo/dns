ชื่อตามสุขภาพของพูล เพื่อให้ทราฟฟิกย้ายไปยังพูลที่ปกติโดยอัตโนมัติ

<Aside type="caution" title="รอการพัฒนาโมดูล dns-lb">
เฟสนี้ยังไม่พร้อมสำหรับการดำเนินการ เนื่องจากขึ้นอยู่กับโมดูล `dns-lb` ของ Terraform ซึ่งเป็นงานต่อเนื่องจากแผนปัจจุบัน โดยติดค้างอยู่ที่การกำหนดรูปแบบ wire format ของ `lb_record` หน้านี้จัดทำเอกสารการออกแบบที่ตั้งใจไว้เพื่อให้โครงสร้างครบถ้วน ขั้นตอนที่ดำเนินการได้จะเพิ่มเติมพร้อมกับโมดูล
</Aside>

## การออกแบบที่วางแผนไว้

สแตกตัวกระจายโหลด DNS ประกอบด้วยทรัพยากร F5 XC สามรายการและเรกคอร์ดในโซน:

| ทรัพยากร | บทบาท |
| --- | --- |
| `xcsh_dns_lb_health_check` | ตรวจสอบสมาชิกแต่ละราย (HTTP, HTTPS, TCP, ICMP หรือ UDP) เพื่อตัดสินสุขภาพของพูล |
| `xcsh_dns_lb_pool` | ชุดสมาชิกพร้อมโหมดการกระจายโหลด (`ROUND_ROBIN`, `PRIORITY`, …) และการอ้างอิงถึงการตรวจสอบสุขภาพ |
| `xcsh_dns_load_balancer` | กฎที่เลือกพูลต่อคำขอ พร้อมพูลสำรอง |
| `lb_record` (ใน `xcsh_dns_zone`) | เชื่อมโยงชื่อในโซนกับตัวกระจายโหลด DNS |

โมดูล `dns-lb` จะแสดงออกสิ่งเหล่านี้ และโมดูลโซนจะเพิ่มรายการ `lb_record` ที่ชี้ไปยังตัวกระจายโหลด — เพื่อให้ `terraform apply` เพียงครั้งเดียวสร้างเส้นทางการล้มเหลวสำรองทั้งหมด

## การสาธิตที่วางแผนไว้

เมื่อโมดูลพร้อมใช้งาน การสาธิตการล้มเหลวสำรองจะ:

1. ปรับใช้สองพูล (หลักและรอง) ที่อยู่เบื้องหลังตัวกระจายโหลด DNS พร้อมการตรวจสอบสุขภาพ
2. แก้ไขชื่อที่กระจายโหลดและยืนยันว่าส่งคืนคำตอบของพูลหลัก
3. ทำให้พูลหลักไม่ปกติและยืนยันว่าการแก้ไขล้มเหลวสำรองไปยังพูลรอง — ประตูความพร้อมจะ
   สำรวจ `dig` จนกว่าคำตอบจะเปลี่ยนแปลง
4. คืนค่าพูลหลักและยืนยันการกลับคืน
