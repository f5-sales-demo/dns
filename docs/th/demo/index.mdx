คู่มือนี้จะนำคุณผ่าน **การฝึกซ้อม DNS แบบครบวงจร** บน F5 Distributed Cloud ที่ขับเคลื่อนด้วย Terraform
โดยมีโครงสร้างเป็นสี่ขั้นตอนที่ผู้ดำเนินการหรือผู้ช่วย AI สามารถรันได้ตั้งแต่ต้นจนจบ แต่ละ
ขั้นตอนเป็น idempotent: การรันซ้ำจะนำไปสู่สถานะเดิมเสมอ

## ขั้นตอนของการฝึกซ้อม

| ขั้นตอน | เป้าหมาย |
| --- | --- |
| [ขั้นตอนที่ 1 — สร้าง](/dns/th/demo/phase-1-build/) | ปรับใช้โซน DNS หลักด้วย Terraform พร้อมเชื่อมต่อ remote state และ CI |
| [ขั้นตอนที่ 2 — ตรวจสอบ](/dns/th/demo/phase-2-validate/) | ยืนยันว่าโซนสามารถ resolve ได้บนอินเทอร์เน็ตสาธารณะและแผนเป็น idempotent |
| [ขั้นตอนที่ 3 — สลับการทำงาน](/dns/th/demo/phase-3-failover/) | เพิ่ม DNS load balancer พร้อม failover ที่ตรวจสอบสุขภาพ *(รอโมดูล DNS-LB)* |
| [ขั้นตอนที่ 4 — รื้อถอน](/dns/th/demo/phase-4-teardown/) | ทำลายออบเจกต์ที่จัดการอยู่หลังจากได้รับการยืนยันอย่างชัดเจน |

## ข้อกำหนดเบื้องต้น

- **Terraform** ≥ 1.5
- Provider **`f5-sales-demo/xcsh`** ≥ 3.62.0 (namespace เฉพาะระบบจะถูกกำหนดค่าเริ่มต้นโดยอัตโนมัติ)
  ที่ resolve จาก Terraform registry — หรือ local build ผ่าน `dev_overrides`
- **F5 XC API token** ที่มีสิทธิ์เข้าถึง namespace `system`
- **Azure CLI** ที่ลงชื่อเข้าใช้ด้วยสิทธิ์ Contributor บน subscription สำหรับการตั้งค่า state
  backend ครั้งแรก

<Aside type="caution">
โดเมนที่ใช้ที่นี่ถูก delegate ให้กับ F5 XC ดังนั้น record ที่คุณสร้างจะ resolve ได้บนอินเทอร์เน็ตสาธารณะ
ใช้โดเมนที่คุณเป็นเจ้าของและตั้งใจจะจัดการ — แผนนี้ถูกออกแบบให้ขับเคลื่อนด้วยตัวแปรเพื่อให้คุณสามารถกำหนดเป้าหมายโดเมนของคุณเองได้
</Aside>
