चरण 4 योजना द्वारा बनाई गई हर चीज़ को हटा देता है। `terraform destroy` F5 XC API के माध्यम से प्रबंधित `xcsh_dns_zone`
(और उसके रिकॉर्ड) को हटाता है और रिमोट स्टेट को अपडेट करता है।

<Aside type="caution">
डिस्ट्रॉय अपरिवर्तनीय है और डोमेन के लिए सार्वजनिक DNS रिकॉर्ड हटा देता है। आगे बढ़ने से पहले लक्ष्य डोमेन और
टेनेंट की पुष्टि करें — आपके परिवेश में क्रेडेंशियल और इनपुट तय करते हैं कि क्या हटाया जाएगा।
</Aside>

## डिस्ट्रॉय

<Steps>

1. पुष्टि करें कि आपका परिवेश इच्छित टेनेंट और डोमेन को लक्षित करता है:

   ```sh
   echo "$XCSH_API_URL"
   grep '^domain' terraform/terraform.tfvars
   ```

2. समीक्षा करें कि क्या नष्ट किया जाएगा:

   ```sh
   cd terraform
   terraform plan -destroy
   ```

3. योजना की समीक्षा के बाद डिस्ट्रॉय करें:

   ```sh
   terraform destroy
   ```

</Steps>

## हटाने की पुष्टि करें

F5 XC से ज़ोन के हट जाने की पुष्टि करें (HTTP `404` की अपेक्षा करें):

```bash
curl -s -o /dev/null -w '%{http_code}\n' \
  -H "Authorization: APIToken xF5XC_API_TOKENx" \
  "xF5XC_API_URLx/api/config/dns/namespaces/system/dns_zones/xF5XC_DOMAINx"
```

एक बार जब डेलीगेट किए गए नेमसर्वर रिकॉर्ड हटा देते हैं, तो सार्वजनिक रिज़ॉल्यूशन बंद हो जाता है।

## क्या बचता है

Azure स्टेट बैकएंड (संसाधन समूह, स्टोरेज अकाउंट, कंटेनर) `terraform destroy` द्वारा **नहीं** हटाया जाता —
यह स्टेट रखता है और रन के दौरान पुनः उपयोग किया जाता है। स्टेट फ़ाइल बनी रहती है, अब एक खाली कॉन्फ़िगरेशन दर्ज करती है। बैकएंड को केवल तभी हटाएं जब आप परिवेश को पूरी तरह सेवामुक्त कर रहे हों, Azure CLI के साथ:

```sh
az group delete --name f5-sales-demo-tfstate --yes
```

पुनर्निर्माण के लिए, [चरण 1 — बिल्ड](/dns/demo/phase-1-build/) से फिर शुरू करें।
